# TRACÉA — Document maître produit, méthode & décisions
_Version complète cumulative — avril 2026_

> Objectif de ce document : rassembler sans écraser les décisions prises, la vision produit, les limites éthiques, les bases scientifiques, les choix de méthode et les prochaines briques à construire pour faire de TRACÉA un produit utile, vendable et cohérent.

---

# 1. Intention fondamentale

TRACÉA est né d’une intention humaine forte : aider une personne qui subit ses émotions à ne plus se croire cassée, mauvaise, incontrôlable ou condamnée à se détruire pour fuir ce qu’elle ressent.

L’objectif profond n’est pas seulement de “calmer” une émotion.

L’objectif est d’aider l’utilisateur à :

- traverser un moment émotionnel intense sans se perdre ;
- comprendre ce qui se passe en lui, sans être jugé ;
- revenir au corps quand le mental s’emballe ;
- reconnaître qu’il n’est pas le problème ;
- identifier ce qui l’aide réellement ;
- voir, dans le temps, ce qui revient et ce qui change ;
- gagner du temps dans sa vie réelle en ne restant pas seul face à ses réactions.

TRACÉA ne doit jamais faire sentir à l’utilisateur qu’il est le problème.

---

# 2. Ce que TRACÉA n’est pas

TRACÉA n’est pas :

- une thérapie ;
- un diagnostic ;
- un outil médical ;
- un substitut à un suivi psychologique ou psychiatrique ;
- un coach de développement personnel ;
- une application qui interprète l’utilisateur ;
- une IA qui explique la vie de la personne à sa place ;
- un outil qui classe ou évalue la valeur émotionnelle d’une personne.

TRACÉA ne doit jamais :

- diagnostiquer ;
- dire “tu es…” dans un sens identitaire ;
- attribuer une cause psychologique ;
- affirmer un traumatisme ;
- parler de schéma d’abandon, de dépendance, de trouble, de pathologie ou de mécanisme psychologique personnel sans que l’utilisateur le nomme lui-même ;
- enfermer l’utilisateur dans une lecture de lui-même.

---

# 3. Ce que TRACÉA est

TRACÉA est :

- un outil de régulation émotionnelle en temps réel ;
- un espace de retour au corps ;
- un miroir sobre et non intrusif ;
- une structure pour traverser sans fuir ;
- un appui pour retrouver un peu de stabilité ;
- un système qui aide à voir ce qui revient, sans interpréter ;
- un outil qui donne du sens par la clarté, pas par l’analyse psychologique.

Formulation synthétique :

> TRACÉA aide l’utilisateur à arrêter de se croire le problème quand ça déborde.

Autre formulation centrale :

> Tu n’es pas instable. Tu es submergé.

Cette phrase n’est pas une promesse médicale. C’est une relecture physiologique et humaine du débordement émotionnel.

---

# 4. Promesse produit élargie

La promesse produit ne doit pas être réduite à une seule phrase trop restrictive.

TRACÉA doit permettre :

- de revenir à soi quand ça déborde ;
- de comprendre ce qui se passe en soi, sans interprétation ;
- de reconnaître les réactions qui se déclenchent ;
- d’identifier les besoins présents derrière l’intensité émotionnelle ;
- de voir ce qui revient dans le temps ;
- de voir ce qui aide déjà ;
- de développer une lucidité sur soi sans jugement ;
- de transformer une réaction subie en mouvement plus conscient.

Important : comprendre ses schémas reste une ambition du produit, mais cette compréhension doit émerger par observation, jamais par interprétation imposée.

TRACÉA ne dit pas :

> “Voici ton schéma.”

TRACÉA montre :

> “Ce type de situation revient souvent.”
> “Tu choisis souvent cet appui.”
> “Ce besoin apparaît régulièrement dans tes traversées.”

L’utilisateur fait le lien lui-même.

# 5. Le nœud stratégique identifié

Le produit actuel fonctionne dans le moment.

Il aide à :

- faire une traversée courte ;
- revenir au corps ;
- poser un besoin ;
- recevoir une synthèse ;
- clôturer proprement.

Mais il ne crée pas encore assez de valeur dans le temps.

Le problème actuel n’est pas que TRACÉA est vide. Le problème est que sa valeur est encore trop invisible.

Diagnostic :

- la valeur immédiate existe ;
- la valeur cumulative est trop faible ;
- les répétitions ne sont pas assez visibles ;
- la mémoire produit n’est pas assez incarnée côté utilisateur ;
- l’utilisateur ne voit pas encore clairement pourquoi revenir ;
- l’utilisateur ne voit pas encore assez ce que TRACÉA lui apporte après plusieurs usages.

Formulation clé :

> TRACÉA agit dans le moment, mais doit maintenant révéler ce qu’il construit dans le temps.

# 6. Base scientifique et cadre de référence

TRACÉA doit s’appuyer sur des bases scientifiques réelles, sans se transformer en application thérapeutique ni utiliser un jargon clinique dans l’expérience utilisateur.

La base scientifique est un appui de conception, pas un argument d’autorité affiché partout.

## 6.1 Neurophysiologie du stress

TRACÉA s’appuie sur l’idée que les émotions intenses ne sont pas uniquement des pensées. Elles impliquent le corps.

Points d’appui :

- activation du système nerveux autonome ;
- mobilisation sympathique ;
- réactions de survie : lutte, fuite, figement ;
- accélération cardiaque ;
- respiration plus courte ;
- tension musculaire ;
- réduction de la clarté cognitive en état d’activation.

Traduction produit :

- commencer par le corps ;
- réduire la charge cognitive ;
- ne pas demander une analyse trop tôt ;
- ralentir avant de réfléchir ;
- proposer des gestes simples, concrets, accessibles.

## 6.2 Régulation émotionnelle

TRACÉA s’appuie sur des principes de régulation émotionnelle :

- une émotion est une réponse adaptative ;
- l’émotion n’est pas une preuve que la personne est “mauvaise” ou “cassée” ;
- nommer ce qui est là peut aider à diminuer l’intensité ;
- revenir au corps peut soutenir la régulation ;
- l’action alignée doit rester petite, faisable et non performative.

Traduction produit :

- nommer sans enfermer ;
- proposer des choix simples ;
- éviter les grandes interprétations ;
- orienter vers un micro-geste ;
- renforcer l’idée que traverser est déjà un mouvement.

## 6.3 Corps avant mental

Une décision centrale du produit est :

> Corps avant mental.

Cela signifie :

- ne pas commencer par “pourquoi je ressens ça ?” ;
- commencer par “où est-ce que ça se passe dans mon corps ?” ;
- ne pas obliger l’utilisateur à comprendre avant de se réguler ;
- ne pas transformer la traversée en analyse.

## 6.4 Approches théoriques utilisées comme inspiration

TRACÉA peut s’inspirer de principes issus de :

- thérapies cognitivo-comportementales ;
- thérapie d’acceptation et d’engagement ;
- approches trauma-informed ;
- psychoéducation émotionnelle ;
- travaux sur l’affect labeling ;
- pratiques d’ancrage corporel et attention sensorielle.

Mais ces approches ne doivent pas être présentées comme une promesse thérapeutique.

Elles servent à concevoir un outil plus juste, pas à se positionner comme soin.

## 6.5 Comportements observables

TRACÉA peut s’appuyer sur des éléments observables :

- situations qui reviennent ;
- émotions sélectionnées ;
- sensations corporelles choisies ;
- besoins nommés ;
- gestes d’ancrage utilisés ;
- actions alignées choisies ;
- fréquence d’usage ;
- types d’appuis sélectionnés.

TRACÉA peut montrer ces éléments sous forme d’observation.

Il ne doit pas conclure à la place de l’utilisateur.

## 6.6 Limite scientifique et légale

TRACÉA peut dire :

- “Tu as souvent choisi cet appui.”
- “Cette émotion revient dans plusieurs traversées.”
- “Tu as noté ce besoin plusieurs fois.”
- “Ton corps peut réagir fort quand il se sent en alerte.”

TRACÉA ne doit pas dire :

- “Tu as un trauma d’abandon.”
- “Tu évites les conflits.”
- “Tu es anxieux.”
- “Tu as progressé de 45 %.”
- “Ton schéma est…”
- “Tu es comme ça parce que…”

# 7. Cadre éthique

Le cadre éthique de TRACÉA est central.

L’utilisateur arrive souvent dans un état vulnérable. Le produit doit respecter cet état.

Principes :

- ne pas manipuler ;
- ne pas créer de peur ;
- ne pas utiliser la honte comme levier ;
- ne pas vendre au moment où l’utilisateur est le plus fragile ;
- ne pas cacher la sortie ;
- ne pas tromper avec des boutons qui ne font pas ce qu’ils annoncent ;
- ne pas dévaloriser l’option gratuite ;
- ne jamais faire sentir que l’utilisateur est seul s’il refuse l’abonnement.

Décisions déjà appliquées :

- “Terminer” doit vraiment terminer ;
- “Retour à l’accueil” doit vraiment sortir ;
- “Continuer seul” a été remplacé ;
- “Repartir de zéro” a été supprimé ;
- les paywalls ont été rendus plus clairs et plus dignes.

# 8. Les phrases vérité TRACÉA

## 8.1 Statut produit

Les phrases vérité TRACÉA ne sont pas un détail cosmétique.

Elles sont un pilier émotionnel du produit.

Elles incarnent la promesse :

> “Tu n’es pas le problème quand ça déborde.”

Elles apportent une relecture juste sans interpréter l’utilisateur.

## 8.2 Rôle

Elles servent à :

- enlever la honte ;
- redonner une lecture juste ;
- apaiser l’auto-jugement ;
- reconnecter l’utilisateur à sa valeur ;
- rappeler que l’intensité ne définit pas la personne.

## 8.3 Contraintes

Elles doivent être :

- universelles ;
- non personnalisées ;
- non diagnostiques ;
- non psychologiques ;
- courtes ;
- respirantes ;
- incarnées ;
- compatibles avec la fin d’une session.

Elles ne doivent pas :

- expliquer la vie de l’utilisateur ;
- nommer un trauma ;
- affirmer une cause ;
- devenir du coaching ;
- donner une injonction.

# 9. Ce que l’utilisateur paie réellement

L’utilisateur ne paie pas seulement pour des fonctionnalités.

Il paie pour :

- ne plus se sentir seul dans ses moments de débordement ;
- retrouver un point d’appui ;
- revenir plus vite à ce qui l’aide ;
- voir ce qui se répète ;
- développer une lucidité plus douce sur ce qu’il vit ;
- se sentir accompagné sans être analysé ;
- pouvoir revenir à un espace fiable quand ça monte.

L’abonnement doit donc vendre une continuité, pas une simple session.

---

# 10. Problème du modèle actuel

TRACÉA est actuellement plus proche d’un outil ponctuel que d’un accompagnement dans le temps.

Ce qui est déjà bon :

- la traversée courte ;
- la session approfondie ;
- le ton ;
- les paywalls corrigés ;
- les phrases vérité ;
- la cohérence émotionnelle ;
- la logique corps avant mental.

Ce qui manque pour rendre le produit vendable :

- une valeur cumulative visible ;
- une mémoire utile visible ;
- une raison de revenir entre deux crises ;
- une manière de montrer les répétitions sans interpréter ;
- une manière de faire sentir l’évolution sans score brutal ;
- une meilleure articulation premium/free.

# 11. Scores et progression

Décision importante :

> Ne pas afficher de scores bruts pour l’instant.

Raison :

- risque de mentalisation ;
- risque de comparaison ;
- risque de jugement ;
- risque que l’utilisateur se sente nul si le score ne monte pas ;
- incompatibilité possible avec l’état émotionnel de l’utilisateur.

Mais l’idée de progression ne doit pas être abandonnée.

Elle doit être traduite autrement :

- observation douce ;
- répétition visible ;
- phrases qualitatives ;
- repères concrets ;
- changements observables mais non chiffrés.

Exemples autorisés :

- “Ce besoin revient souvent.”
- “Tu choisis souvent cet appui.”
- “Tu as déjà utilisé ce geste plusieurs fois.”
- “Ce type de moment apparaît dans plusieurs traversées.”

À éviter :

- “Tu as progressé de X %.”
- “Tu es plus stable.”
- “Tu te régules mieux.”
- “Tu es passé de 42 à 67.”

---

# 12. Patterns et schémas sans interprétation

L’objectif “comprendre ses schémas” reste important.

Mais TRACÉA ne doit pas nommer un schéma psychologique à la place de l’utilisateur.

Approche validée :

> montrer les répétitions pour que l’utilisateur puisse faire ses propres liens.

Exemples :

- “Dans plusieurs traversées, tu as choisi : ralentir.”
- “Ce besoin revient souvent : être respecté.”
- “Tu as souvent noté une tension dans la poitrine.”
- “Ce type de situation apparaît régulièrement.”

Interdit :

- “Tu as un schéma d’abandon.”
- “Tu cherches à être validé.”
- “Tu fuis le conflit.”
- “Tu réagis comme ça parce que…”

# 13. Les 3 futures briques produit à construire

## 13.1 Lecture de répétition

Objectif :

- rendre visible ce qui revient ;
- sans interprétation ;
- sans analyse psychologique.

Forme possible :

- “Ce qui revient souvent”
- “Ce que ton corps signale souvent”
- “Ce que tu nommes souvent”
- “Les besoins qui apparaissent plusieurs fois”

## 13.2 Lecture du corps

Objectif :

- reconnecter l’utilisateur à la dimension physiologique ;
- montrer que le corps participe au débordement ;
- enlever la honte.

Forme possible :

- “Quand ça monte, ton corps peut prendre le dessus.”
- “Tu as souvent situé l’intensité dans…”
- “Ton retour au calme passe souvent par…”

## 13.3 Lecture des appuis

Objectif :

- montrer ce qui aide déjà ;
- rendre le produit utile au prochain moment difficile ;
- créer un “kit de retour”.

Forme possible :

- “Ce qui t’aide souvent”
- “Tes appuis les plus utilisés”
- “À retrouver quand ça remonte”

# 14. Paywalls et monétisation

Décisions prises :

- le produit ne doit pas vendre par la peur ;
- pas de “repartir de zéro” ;
- pas de “continuer seul” ;
- pas de bouton qui ment ;
- sortie gratuite digne ;
- CTA payant explicite ;
- prix transparent.

Paywalls corrigés :

1. `/app/post-session`
2. soft-limit `/app/traversee-courte`
3. PaywallSection inline `/app/session`
4. Paywall dur `Paywall.tsx`
5. Auth-wall `/app/session`

Décision stratégique :

- ne pas vendre en sortie fragile ;
- privilégier le retour utilisateur ou l’accueil app ;
- réfléchir à un paywall qui convertit sans casser l’état émotionnel ;
- envisager l’essai gratuit 7 jours seulement après avoir clarifié la valeur premium.

# 15. Audit coût technique

Constats :

- traversée courte = aucun coût IA ;
- session approfondie = coût IA faible ;
- coût moyen utilisateur estimé très bas ;
- marge brute très élevée sur 9 €/mois ;
- essai gratuit 7 jours techniquement peu risqué.

Mais décision actuelle :

> Ne pas activer un essai gratuit simplement parce que le coût est bas.

Raison :

- le produit doit d’abord être assez fort pour convertir ;
- la valeur premium doit être clarifiée ;
- l’essai gratuit n’a de sens que si l’utilisateur découvre une vraie valeur.

---

# 16. Mémoire et moteur premium

Point critique identifié :

- le moteur mémoire, scores, patterns et historique pourrait exister techniquement ;
- mais la valeur n’est pas assez visible côté utilisateur ;
- il faut vérifier que la mémoire évolutive fonctionne réellement ;
- il faut vérifier si `/api/tracea/summarize` est bien appelé ;
- si ce n’est pas le cas, la mémoire premium peut être morte en pratique.

Priorité technique future :

1. vérifier fonctionnement réel de la mémoire ;
2. vérifier alimentation des résumés ;
3. rendre visible ce qui est utile ;
4. éviter les scores bruts.

# 17. Méthode de travail validée

La méthode doit être exigeante sans être enfermante.

Principes :

## 17.1 Construire par brique

- une brique à la fois ;
- un objectif clair ;
- un périmètre clair ;
- pas de mélange design / sécurité / produit / wording dans un même patch.

## 17.2 Aller au bout de chaque brique

- ne pas survoler ;
- ne pas dire “on corrigera plus tard” si le problème est identifié ;
- optimiser pendant la création quand c’est nécessaire ;
- valider avant de passer à la suite.

## 17.3 Ne pas laisser de dette mentale

- pas de “il faudra se souvenir” ;
- tout point important doit être intégré au document ou à une backlog claire ;
- ce n’est pas à Alyson de tout retenir.

## 17.4 Rester flexible

Le document est un guide, pas une prison.

Il doit :

- protéger ;
- clarifier ;
- éviter les dérives ;
- mais ne jamais empêcher une bonne idée.

## 17.5 Catégoriser les problèmes

- Critique : à traiter immédiatement.
- Important : à corriger proprement avant validation.
- Amélioration : à documenter, mais ne bloque pas tout si elle n’impacte pas la cohérence produit.
